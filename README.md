# Формула Элегантности

Сайт шоурума женской классической одежды на адресу: Москва, ул. Неглинная, 8/10, 3-й этаж.

Исходники и серверный движок: ветка `main`. Публичная статическая демоверсия:
https://kibosh13.github.io/showroom-formula-elegantnosti/
Готовые файлы демонстрации: ветка `gh-pages`. Репозиторий:
https://github.com/Kibosh13/showroom-formula-elegantnosti

## Возможности

Главная, каталог с фильтрами и поиском, карточки товаров, избранное на устройстве,
готовые образы, капсулы, услуги, цены, галерея, контакты и карта, запись и бронирование,
заявки на подарочные сертификаты, простые процентные промокоды, отзывы с модерацией.
Заявки, каталог, настройки и отзывы сохраняются в D1; загруженные фотографии — в R2.
Панель `/admin`: редактирование товаров, обложек, галерей (URL в нужном порядке),
подборок и справочника категорий, контактов, услуг, промокодов; CRM и экспорт CSV.
Администратор видит заявки и настройки; контент-менеджер — товары, подборки и отзывы.

## Состояние перед реальным запуском

101 модель из присланного каталога и 6 предложений сочетаний. 304 фотографии одежды
предоставлены заказчиком; 4 повторных файла исключены. 91 карточка содержит несколько
фото с миниатюрами, переключением и увеличением. Хиро — дизайн-концепция. Семь фотографий шоурума предоставлены заказчиком 16.10.2026.
Названия и цвета описаны по фотографиям; 10 артикулов прочитаны на снимках.
Прайс, размеры, состав, остатки и официальные названия ещё не предоставлены: цена
отображается как «Цена по запросу», размеры и наличие уточняются. Эти поля не выдуманы.
Соответствие исходных файлов моделям сохранено в data/catalogue-source.json.
Техническая оптимизация фото в WebP сохраняет одежду и цвета. Для 24 скриншотов
SVG viewport отображает область фотографии без шапки и нижней панели браузера.
Юридические тексты нужно получить от заказчика.
Формы сохраняют запрос; визит и резерв подтверждает менеджер. Учёт занятых слотов,
автоматическая блокировка остатков и автоматическая выдача оплаченных сертификатов
пока не реализованы. Онлайн-оплата не подключена.
Telegram и email подготовлены в серверном адаптере, но без ключей не отправляются.
WhatsApp и Telegram ведут на указанный номер. Telegram требует разрешённого поиска по номеру в настройках аккаунта. Для MAX предусмотрен поиск по номеру с копированием; прямую ссылку на профиль можно добавить в настройках.
Отзывы не выдуманы. Публичная индексация отключена до согласования реального контента.

## Технологии

Vinext / React / TypeScript, Cloudflare Worker, D1 и R2. Серверные URL товаров и
подборок, метатеги, Open Graph, sitemap, адаптивность, локальные шрифты Cormorant
Garamond и Montserrat. Чувствительные сведения не помещаются в клиентский код.

## Переменные окружения

ADMIN_PASSWORD — ключ администратора, CONTENT_PASSWORD — ключ контент-менеджера.
TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID — уведомления в чат команды.
RESEND_API_KEY, NOTIFICATION_EMAIL, NOTIFICATION_FROM — email-уведомления команде.
Ключи хранить в секретных переменных хостинга; для локальной разработки — в
игнорируемом `.dev.vars`. Пример с названиями находится в `.env.example`.

## Проверка

Пройдены TypeScript, сборка Vinext, локальная проверка API: формы, сохранение контекста,
CRM, промокоды, сертификаты, авторизация и ограничения ролей, редактирование товаров.
Проверены браузером мобильный каталог, фильтры, возврат, размер и успешная форма.
Внешние уведомления и платежи требуют данных и отдельной проверки после подключения.
Тестовые записи остаются только в локальной базе; в архив и production не включаются.

## Локальная разработка

Используйте Sites project helpers для установки, сборки и упаковки.
`npm run dev -- --port 5187 --hostname 127.0.0.1`
После генерации схемы применить миграции к локальной D1 по инструкциям Sites.

## GitHub Pages: безопасная демонстрация

`npm ci` и `npm run build:demo` (Node 22.13+). Результат — локальный `dist-demo/`,
игнорируемый в main. Для просмотра: `npm run preview:demo -- --port 5187` и адрес
`http://127.0.0.1:5187/showroom-formula-elegantnosti/`.

После изменений в main workflow Publish static demo автоматически собирает сайт,
обновляет только изменившиеся файлы ветки gh-pages обычным коммитом без force-push
и публикует Pages через официальный deployment artifact. Архивы исходников,
локальные базы, зависимости и сборки сервера в репозиторий не попадают.
Демонстрационная сборка не читает D1, R2, .dev.vars или секреты GitHub.
Все 122 адреса экспортируются в HTML и открываются напрямую после перезагрузки.

В демоверсии работают каталог, фильтры, поиск, варианты товаров, образы, капсулы,
информационные страницы и локальное избранное. Отключены отправка заявок,
онлайн-запись, резервирование, запрос обратного звонка, отправка отзывов,
покупка и выдача сертификатов, проверка промокодов, бонусы, CRM, вход в CMS,
редактирование и загрузка файлов, Telegram/email-уведомления и серверная аналитика.
Серверные запросы из демонстрации не выполняются; формы не собирают личные данные.
Телефон, WhatsApp, Telegram и внешние карты остаются обычными ссылками.

## Индексация демонстрации и будущего боевого сайта

Каждый HTML демонстрации, включая 404, содержит `noindex, nofollow, noarchive`
для robots, Googlebot и Bingbot. Добавлен robots.txt с Disallow: /.
На GitHub project Pages robots.txt находится под путём проекта; главным запретом
индексации являются метатеги каждого HTML. Это не ограничение доступа: демо публично.

Полноценный серверный сайт также закрыт по умолчанию. Для боевого запуска задайте
в окружении хостинга `SITE_URL=https://ваш-домен` и `SITE_INDEXING=enabled`.
После этого метатеги публичных страниц разрешают индексацию, robots.txt разрешает
обход и указывает sitemap с боевым доменом. Панель, API и служебные страницы
остаются закрыты от поисковиков. Переключатель не влияет на GitHub Pages:
демонстрационная сборка всегда остаётся noindex.

## Что остаётся перед боевым запуском

Получить фото входа/фасада, размеры, остатки, цены и условия услуг;
согласовать юридические тексты, сертификаты и бонусную программу; выбрать домен
и серверный хостинг; настроить отдельные production D1/R2 и секреты; подключить
оплату, уведомления и аналитику, затем проверить полный сценарий с заказчиком.
Адреса Telegram/MAX должны быть подтверждены владельцем. Секреты передавать
через защищённые настройки хостинга, а не коммитить в Git.

## Pop-up персональной скидки

Появляется через 20 секунд после загрузки первого посещения. Не открывается поверх
другого окна или во время работы с полем формы; страница записи также исключена.
Показ один раз за сессию; после закрытия пауза 7 дней, после отправки — 30 дней.
Закрытие сохраняет страницу и прокрутку, доступны Escape и кнопки закрытия.
В `/admin` → Настройки редактируются включение, заголовок, предложение/размер скидки,
текст, кнопка, фото, срок действия, задержка и оба периода повторного показа.

В серверной версии телефон проходит проверку, заявка `discount` сохраняется в CRM
с источником `popup_discount`, временем, URL, referrer и UTM. Переход из успешного
состояния к стилисту сохраняет источник. Подписка на рекламные рассылки не создаётся.
Защита: проверка origin, скрытое поле и не более 5 заявок на нормализованный телефон
в час. События pop-up учитываются только с разрешённой аналитикой, без телефона.

На GitHub Pages окно демонстрирует предложение, а поле телефона и отправка отключены.
Доступна связь со стилистом; ложного подтверждения сохранения номера нет.
Для запуска серверной аналитики примените новую миграцию
`drizzle/0001_nice_bulldozer.sql` к production D1 перед обновлением движка.
Проверка сценариев: `node scripts/test-popup.mjs`.
Фотография гримёрки подключена в `makeupImage`. Дополнительные фото интерьера редактируются в `spaceGallery`.
